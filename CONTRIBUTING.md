# Contributing

Everything here is held to one rule: **a claim ships with the evidence that lets a stranger check
it.** That applies to code, to the audit table and to prose. The three ways to contribute, in the
order we need them most:

## 1. Put your benchmark in the audit table

This is the contribution the project most needs: a verdict on a benchmark we did not build, with
a field mapping its authors agree with. Open an issue with the **Add a benchmark** template, or
send a pull request that adds one entry to `nulltest_audit_manifest.json`:

```json
{
 "name": "yourproject/benchmark",
 "paper": "Title (venue, year)",
 "url": "https://raw.githubusercontent.com/.../items.jsonl",
 "cache_as": "yourproject_benchmark.jsonl",
 "format": "jsonl",
 "text_field": "statement",
 "label_field": "label",
 "stratum_field": "category",
 "label_positive": ["false"],
 "label_kind": "true_vs_false_statement",
 "note": "what the items are, how many, how the two classes were produced"
}
```

Question-answer corpora that keep right and wrong answers on one row use `explode` and `split`
instead of `text_field`/`label_field`; see the TruthfulQA and HaluEval entries. Rules:

- The URL must serve the exact bytes a reader can fetch themselves. The table records a URL and a
  sha256, never a copy; `audit_cache/` is gitignored for that reason.
- `label_kind` must be one of the kinds described at the top of the manifest, because a surface hit
  means something different for an entity list than for a sentence corpus.
- Run it: `python3 nulltest_audit.py --only yourproject/benchmark --jobs 4`. Paste the row into the
  PR. We re-run it before merging; the committed `nulltest_audit_results.json` is regenerated by
  us, not edited by hand.
- A DISQUALIFIED verdict on your own benchmark is welcome here. It is a measurement about a corpus,
  not a finding about its authors, and the table already has four of ours at the top.

## 2. Report a verdict you believe is wrong

Use the **Wrong verdict** template. The useful report has three things: the receipt (`--json`
output, which carries the file hash and the tool hash), the command you ran, and what you expected.
Run `python3 nulltest.py FILE --check receipt.json` first: if it says DIVERGES, that is a bug in
the tool and we want it; if it REPLAYS, the disagreement is about what the result means, which is
also worth a conversation.

## 3. Change the tool

```bash
python3 -m unittest discover -s tests -v          # 51 stdlib tests, a few seconds
bash nulltest_parity.sh                           # browser engine == CLI, cell by cell
python3 nulltest.py --selftest --seeds 25 --n-perm 200
```

Rules the CI enforces and reviewers will hold you to:

- **Every probe change must come with a test that fails without it.** Each test in
  `tests/test_nulltest.py` names the regression it would catch.
- **`nulltest.js` must stay bit-identical to `nulltest.py`.** A change to one is a change to both,
  and `nulltest_parity.sh` has to pass. Python's `random.Random`, `round()` and sort order are
  reimplemented in the JS on purpose; do not "simplify" them.
- **Any edit to `nulltest.py` changes its sha256 and invalidates the three certificates**
  (`nulltest_grid.json`, `nulltest_parity.json`, `nulltest_audit_results.json`). Regenerate them
  (about an hour on a 4-core machine: 26 minutes for the grid, 29 for the audit) and commit them in the same PR:
  ```bash
  python3 nulltest.py --calibrate --jobs 4 --emit-grid /tmp/nulltest_grid.json && cp /tmp/nulltest_grid.json .
  python3 nulltest_audit.py --jobs 4
  PARITY_EMIT=/tmp/nulltest_parity.json bash nulltest_parity.sh && cp /tmp/nulltest_parity.json .
  ```
  The emitters refuse to write into the repository directory; that is deliberate. A check that
  writes its own evidence proves nothing, and the `read-only` CI job replays every check and fails
  if the tree is dirty afterwards.
- **A new probe needs a grid row where it is live.** The false-positive certificate must exercise
  every probe on no-signal data; the two "word-shaped" rows exist because the NCT-id rows left the
  word and alphabet probes degenerate.
- **Numbers in prose come from files.** README figures quote the certificates; audit prose lives in
  `audit_notes.json` and never carries a number. If you change a measurement, change the file it
  comes from and let the prose follow.
- **Standard library only** in anything a stranger runs. A dependency is something they must trust.

Sign your commits off (`git commit -s`, the Developer Certificate of Origin); the project is
Apache-2.0 and asks for no copyright assignment.
